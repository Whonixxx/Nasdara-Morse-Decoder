# Contributing to Nasdara Morse Decoder

Thank you for your interest in contributing to Nasdara Morse Decoder!

Nasdara Morse Decoder welcomes community contributions, suggestions, bug fixes, and new features.

To maintain code quality, project integrity, compatibility, and respect for intellectual property, all contributors must follow the guidelines below.

By submitting a Pull Request, you acknowledge and agree to the terms established in the repository's LICENSE and this document.

## 1. Original Code and Intellectual Property

All submitted code must be original work created by the contributor or code that the contributor has the legal right and authorization to use and submit.

The following are strictly prohibited:

- Copying code from other DayZ mods, scripts, repositories, or projects without proper authorization.
- Submitting third-party code without identifying its original author and source.
- Removing or modifying copyright notices or author credits.
- Using leaked, decompiled, stolen, or otherwise unauthorized source code.
- Incorporating code that violates another developer's license or intellectual property rights.

Publicly accessible source code does not automatically grant permission to copy, modify, or redistribute it.

If your contribution uses third-party code, libraries, or components, you must clearly disclose:

- Original project and author.
- Source URL or repository.
- Applicable license.
- Any required permissions or conditions for reuse.

The maintainer may request additional information or proof of authorization before accepting a contribution.

## 2. Code Documentation and Comments

All submitted code must be properly documented, commented, and understandable.

Contributors are required to:

- Add clear comments explaining the purpose and behavior of important functions and methods.
- Explain complex logic and non-obvious implementation decisions.
- Use meaningful variable, function, and class names.
- Avoid unnecessary complexity and undocumented code.
- Keep comments accurate and consistent with the actual implementation.
- Provide a clear explanation of the changes in the Pull Request description.

Comments are not required for every line of code. However, important functionality and complex logic must be sufficiently explained to allow the maintainer to understand and maintain the implementation.

Code that is poorly documented, unnecessarily complicated, or difficult to understand may be returned for revision or rejected.

## 3. Pull Request Requirements

Every Pull Request must include:

- A clear description of the proposed change.
- The problem being solved or functionality being added.
- An explanation of how the implementation works.
- A list of modified or added files.
- Testing information and results.
- References and licensing information for any third-party code or dependencies.

Large changes, new systems, or integrations with other DayZ mods should preferably be discussed with the maintainer before implementation.

## 4. Code Quality and Compatibility

All contributions must:

- Follow the existing project structure and coding conventions.
- Avoid unnecessary dependencies.
- Preserve existing functionality unless the change has been discussed and approved.
- Avoid introducing security vulnerabilities, performance issues, or compatibility problems.
- Be compatible with the project's supported DayZ environment.
- Avoid unnecessary modifications to unrelated files or systems.

The maintainer may request modifications, additional documentation, or further testing before accepting a Pull Request.

## 5. Contributor Authorship and Responsibility

Contributors retain ownership and applicable copyright over their original contributions.

By submitting a Pull Request, contributors represent and confirm that:

- They are the original authors of the submitted code or have all necessary legal rights and permissions to submit it.
- Their contribution does not knowingly infringe third-party copyrights, licenses, or intellectual property rights.
- All third-party code and dependencies have been properly disclosed.
- They have the legal authority to grant the permissions established in the repository's LICENSE.

Contributors are responsible for ensuring that their submissions comply with these requirements.

## 7. Review and Acceptance

Submitting a Pull Request does not guarantee acceptance.

Whonixxx is the maintainer and has final authority over the official project.

The maintainer reserves the right to:

- Review and test all submitted code.
- Request changes, explanations, or additional documentation.
- Accept or reject any contribution.
- Reject contributions with unclear authorship, origin, or licensing.
- Modify, replace, refactor, or remove accepted functionality when necessary.
- Discontinue features or integrations at their discretion.

No contribution becomes part of the official project until explicitly accepted and merged by the maintainer.

## 8. No Compensation or Maintenance Obligations

All contributions are voluntary and unpaid.

Submitting or having a contribution accepted does not create any entitlement to financial compensation, royalties, or future benefits.

Acceptance of a contribution does not obligate Whonixxx to maintain, support, preserve, or continue developing that particular functionality.
